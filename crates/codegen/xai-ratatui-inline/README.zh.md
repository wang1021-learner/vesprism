一个用于构建终端应用的 Rust 库，支持**内联视口**（inline viewports）— 动态 UI 元素固定在终端底部，同时保留上方的滚动历史。非常适合构建类聊天界面、命令提示符和交互式终端工具。

## 这是什么？

本 crate 提供用于创建以下终端应用的工具：
- 视口（UI 元素）固定在终端底部
- 视口上方的内容成为终端原生滚动历史的一部分
- 用户可以使用终端内置的滚动功能浏览历史
- 长行自然换行，无截断
- 视口保持可见和可交互，同时历史在上方积累

典型应用场景：
- 底部带输入框的聊天界面
- 带命令历史的交互式 REPL
- 底部带控件的日志查看器
- 任何需要保留输出历史记录的 TUI

## 核心特性

- **内联视口** — UI 保持在底部，内容向上流入滚动历史
- **自然文本流** — 内容正常打印，利用终端原生行为
- **零拷贝文本处理** — 高效的 ANSI 感知文本分段，无内存分配
- **正确的行换行** — 正确处理带 ANSI 序列的终端宽度边界
- **Unicode 支持** — 正确处理 emoji、CJK 字符、组合字符
- **终端调整大小处理** — 使用 RIS（重置为初始状态）的稳健调整大小支持
- **同步输出** — 使用 DCS 协议实现无闪烁渲染
- **跨平台** — 适用于所有终端和多路复用器（tmux、screen 等）

## 架构

### 文本处理

库使用零拷贝方式进行 ANSI 感知的文本分段：
- **anstyle-parse** — ANSI/SGR 感知分段，用于零拷贝行分割
- **零分配** — 返回字符串切片，不复制或分配内存
- **单次遍历解析** — 使用正确的转义序列跟踪一次性处理输入
- **Unicode 支持** — 正确计算 emoji、CJK、组合字符的宽度

### 滚动缓冲区实现

库使用"自然流"方式实现滚动：
1. 将光标定位到视口顶部
2. 打印内容，让终端自然处理换行
3. 添加视口高度数量的新行来预留空间
4. 清除并渲染视口

这种单一实现普遍适用于所有终端和多路复用器，无需特殊模式或变通方法。

### 行尾处理

- **LF (`\n`)** — 标准行尾，移至下一行
- **CRLF (`\r\n`)** — Windows 风格行尾，视为单个换行
- **CR (\r)** — 仅回车，重置光标到行首（覆盖）

## 设计决策

### 为什么 Fork ratatui 的 Terminal？

标准 ratatui Terminal API 不公开内联视口操作所需的内部机制：
- **视口区域访问** — 需要知道当前位置和尺寸
- **直接视口定位** — 必须能够设置视口位置
- **缓冲区管理** — 需要后台缓冲区重置和前一缓冲区访问
- **调整大小计算** — 调整大小时需要访问缓冲区状态

我们复刻的 Terminal 提供这些功能，同时保持与 ratatui API 的兼容性。

### 同步输出

使用 DCS（同步输出）协议实现无闪烁渲染：
- begin/end 标记之间的所有操作是原子的
- 终端每批只更新显示一次
- 消除部分渲染状态

## 性能

- **彩色 JSON**：约 186μs/操作
- **纯文本**：约 75μs/操作  
- **热路径零分配**
- **所有文本处理单次遍历解析**

### 终端调整大小策略

#### 问题

在主屏幕（非备用屏幕）上使用内联视口时，终端调整大小会导致问题：
- 终端在应用收到 SIGWINCH 之前自动重排内容
- 旧视口边框被重排为垃圾文本
- 内置 `autoresize()` 破坏滚动历史
- 光标位置查询（DSR）在快速调整大小时存在竞争条件
- 不同终端不可预测地处理重排

#### 解决方案：RIS（重置为初始状态）

我们使用"核选项"— 完全重置并重新渲染：
1. 发送 RIS（`ESC c`）清除所有内容
2. 重新输出整个滚动历史记录
3. 根据内容量定位视口

这种方法：
- **跨终端一致工作**
- **通过重新输出历史保留滚动**
- **避免不可预测的重排产生的伪影**
- **无光标查询的竞争条件**
- **处理所有调整大小类型**（水平和垂直）
