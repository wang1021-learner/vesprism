# 工作区打开 / 切换 / 侧栏定位 — 实现说明

> 记录 jike-grok-desktop 中与**工作区（cwd）**相关的产品规则与代码落点。  
> 含：点历史进工作区、侧栏不因「当前」置顶、选会话滚动定位、避免全量刷新打散列表。  
> 日期：2026-07-25

---

## 1. 产品规则（大白话）

| 用户操作 | 期望 |
|----------|------|
| 在 **A** 工作区，点开 **B** 的旧对话并在里面操作 | 现在就是 **B 工作区**（Agent + UI「当前」一致） |
| 点 B 的历史 | **B 不要整组飞到侧栏最上面**（只标「· 当前」） |
| **新建对话** | 工作区可在 Composer 里**自己选** |
| Composer / 设置 / 浏览文件夹 | **显式**切换工作区，并持久化 |
| 点侧栏最下面的旧记录 | **不要卡一下后滚动条弹到顶**，尽量停在点的那条附近 |

与 Codex 的差异（便于对照）：

- Codex：进 Project 即激活；Recent 模式下**设计意图**常会 MRU 置顶。  
- 我们：进会话即切到该会话 cwd，但**侧栏排序不靠「当前」硬置顶**，避免一点历史整组上飞。

---

## 2. 核心概念

| 概念 | 含义 | 存储 / 状态 |
|------|------|-------------|
| **当前工作区 `workspaceCwd`** | UI「· 当前」、Composer pill 默认、新建/restart 默认 cwd | React state + `[desktop] workspace_cwd`（config）+ 内存 override |
| **会话 cwd** | 该条历史所属目录；`load_session` 必须用它 | `summary.info.cwd` / 侧栏 `RecentChat.cwd` |
| **工作区列表** | 无独立 Project 注册表 | 由 **当前 cwd ∪ 历史会话 cwd** 去重派生 |

路径比较统一规范化：

```ts
const norm = (p: string) =>
  p.replace(/\\/g, '/').replace(/\/+$/, '').toLowerCase()
```

后端 `set_workspace_cwd` 会 `canonicalize` 并尽量剥掉 Windows `\\?\` 前缀。

---

## 3. 行为矩阵

| 场景 | Agent cwd | UI 当前工作区 | 侧栏顺序 | 是否 `restart_session` |
|------|-----------|---------------|----------|------------------------|
| 点历史（同/跨工作区） | 会话自己的 cwd | **同步为会话 cwd**（并 `set_workspace_cwd`） | **不因 isCurrent 置顶**，按组内最新活跃时间 | 否，`load_session` |
| Composer 选工作区 / 浏览文件夹 | 新 cwd | 更新并持久化 | 排序仍按活跃度（标记变「当前」） | 有会话则 **restart** 空会话 |
| 设置里改工作目录 | 新 cwd | 同上 | 同上 | 变更且 ready 则 restart |
| 新会话（顶栏/侧栏） | `workspace_cwd` | 不变（可先在 pill 改选） | 不变 | `restart_session` |

## 4. 代码落点

### 4.1 点历史 → 进入该工作区（不置顶）

**文件：** `src/App.tsx` → `handleSelectChat`

要点：

1. **乐观** `setActiveChatId(id)`：立刻高亮，侧栏可先展开/定位。  
2. `load_session({ sessionId, cwd })`：`cwd` 必须来自会话（`sessionCwd || fromList.cwd || fallback`）。  
3. 若会话 cwd ≠ 当前 `workspaceCwd`：  
   - `set_workspace_cwd` 持久化  
   - `setWorkspaceCwd` / `setSettingsCwd`  
   - 持久化失败也不阻断已打开的会话，至少 UI 跟上。  
4. **不要**在选会话后无条件 `refreshSessionList()`：全量刷新易打散侧栏 DOM/滚动。  
5. 失败：`setActiveChatId(prevId)` 收回高亮。

```text
点击历史
  → setActiveChatId(id)          // 立刻高亮
  → load_session(id, session.cwd)
  → set_workspace_cwd(session.cwd)  // 若路径变化：现在就是该工作区
  → syncSessionModel
  // 不 refreshSessionList
```

相关依赖：`workspaceCwd` 需进 `useCallback` deps。

### 4.2 显式切换工作区

**文件：** `src/App.tsx`

| 入口 | 函数 |
|------|------|
| Composer 下拉 / 浏览 | `applyWorkspaceCwd` / `browseWorkspace` |
| 设置保存 | `saveSettings`（cwd 变更分支） |

共同逻辑：

- `set_workspace_cwd` 校验目录存在 + 持久化  
- 若会话 `ready`：`restart_session`（清空当前对话）  
- Composer 另有限制：`canSwitchWorkspace` = 就绪且**尚无用户消息**时才显示工作区 pill

---

### 4.3 侧栏分组与排序（不置顶）

**文件：** `src/components/Sidebar/index.tsx` → `groupChatsByWorkspaceThenDate`

- 分组：工作区 → 今天/昨天/… → 会话  
- **`isCurrent` 只影响标签「· 当前」和样式**  
- **排序只按组内最新会话时间**，**不再** `isCurrent` 排最前  

这样：点开 B 的历史会标记 B 为当前，但 B **不会**因为「当前」整组飞到最上面。

默认折叠策略（`isWorkspaceCollapsed`）：

- 未手动记录时：当前工作区展开，其余折叠  
- 激活会话所在工作区会 **强制展开**（见下），保证选中项能挂载

---

### 4.4 侧栏滚动定位（防弹顶）

**文件：** `src/components/Sidebar/index.tsx`

| 问题 | 旧做法 | 现做法 |
|------|--------|--------|
| 点底部旧记录后滚动条飞到顶 | `scrollIntoView({ smooth })` | **只改** `.sidebar-recent-list` 的 `scrollTop` |
| 带动整页/祖先滚动 | scrollIntoView 副作用 | `scrollChildIntoContainer(list, item)` |
| 已在视口内仍乱滚 | 可能 | 在视口内 **直接 return** |
| 对齐时机不对 | 只跟 `activeChatId`，列表重排后不钉 | `needAlign`：id 变 **或** `currentWorkspaceCwd` 变才对齐 |
| 普通刷标题把用户滚走 | 绑太宽 | **不因**普通 `recentChats` 标题更新强制对齐 |

辅助函数：

```ts
function scrollChildIntoContainer(container, child, padding = 8): void
```

流程：

1. render 阶段：检测 `activeChatId` / `currentWorkspaceCwd` 变化 → `needAlignActiveRef = true`  
2. `useLayoutEffect`：强制展开激活会话所在工作区  
3. `useLayoutEffect`：若 needAlign 且节点已挂载 → `scrollChildIntoContainer`；未就绪则保留 needAlign 下轮再试  

列表容器：`ref={listRef}` 挂在 `.sidebar-recent-list`。

### 4.5 后端 cwd 解析与持久化

**文件：** `src-tauri/src/commands.rs`

| 命令 | 作用 |
|------|------|
| `workspace_cwd` | 解析当前工作区：内存 override → config `[desktop] workspace_cwd` → 仓库根兜底 |
| `set_workspace_cwd` | 校验目录、canonicalize、剥 `\\?\`、写 config、更新内存 |
| `list_sessions` | **全量**会话（带 cwd）；传入 cwd 仅用于排序偏好，前端侧栏以分组函数为准 |
| `load_session` | Actor：`GrokSession::resume(id, cwd)` |
| `start_session` / `restart_session` | 使用调用方传入的 cwd |

选历史时前端会 `set_workspace_cwd`，因此后续 **新会话 / restart** 默认跟「正在操作的工作区」一致；用户仍可在 Composer 改选。

### 4.6 顶栏「就绪 / 新会话」（易混淆，顺带说明）

**文件：** `src/components/Header/index.tsx`

- 绿点 **就绪**：`SessionStatus === 'idle'`，可发消息  
- **新会话**：与侧栏 New chat 相同，走 `restartSession`（用当前 `workspace_cwd`）

与工作区规则无关，但是同一顶栏区域。

## 5. 关键状态与 IPC 一览

```text
UI workspaceCwd  ←→  set_workspace_cwd / workspace_cwd
        │
        ├─ Sidebar currentWorkspaceCwd（「· 当前」标记）
        ├─ Composer workspace pill（空会话可切换）
        ├─ start / restart 默认 cwd
        └─ 设置页 settingsCwd

点历史 ──load_session(session.cwd)──► Agent 会话目录
      └──set_workspace_cwd(session.cwd)──► UI + 持久化「当前」
```

## 6. 有意不做 / 注意点

1. **选会话不做全量 `refreshSessionList`**  
   空会话剔除用本地 filter；避免侧栏重挂载导致滚动丢失。

2. **侧栏顺序 ≠ Codex Recent MRU 置顶**  
   只按会话活跃时间；「当前」是标记不是排序主键。

3. **跨工作区点历史会改 config 里的 workspace_cwd**  
   符合「在 B 里操作就是 B」；新建默认跟 B，用户仍可 pill 改选。

4. **显式切工作区会 restart**  
   有内容时 Composer 限制空会话才切；设置里改 cwd 会清对话重建。

5. **路径规范化**  
   比较、分组 key 均应 lower + 统一斜杠，减少 Windows 重复分组。

## 7. 验收清单

- [ ] 同工作区：滚到侧栏最底 → 点旧记录 → 滚动条基本不飞顶，高亮正确  
- [ ] 跨工作区：在 A 点 B 的历史 → 能操作 B 的文件；UI 显示 B 为当前  
- [ ] 跨工作区：B **不会**仅因「变成当前」整组跳到侧栏最顶（位置跟活跃度走）  
- [ ] 新建：Composer 可改选工作区后再发  
- [ ] 显式浏览/设置改工作区：持久化生效，有会话则重建  
- [ ] 恢复失败：高亮回到上一条
