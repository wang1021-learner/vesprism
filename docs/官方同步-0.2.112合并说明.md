## 4. 冲突文件与解决方式

合并命令：

```bash
git remote add upstream https://github.com/xai-org/grok-build.git   # 若尚未添加
git fetch upstream
git merge upstream/main
```

Git 报告 **4 个 content conflict**：

| # | 文件 | 冲突原因 | 解决策略 |
|---|------|----------|----------|
| 1 | `Cargo.lock` | 双方依赖图都变 | 先取 upstream，再靠 `cargo check` 对齐工作区 |
| 2 | `crates/codegen/xai-grok-shell/Cargo.toml` | features 集合不同 | **合并双方**（见 4.1） |
| 3 | `.../acp_session_impl/run_loop.rs` | 上游大改循环；本地改 SetSessionModel 字段 | **上游主体 + 回灌本地字段**（见 4.2） |
| 4 | `.../read_file/mod.rs` | 上游加 skill 全量读与 schema default；本地多为注释语言 | **采用上游实现**（见 4.3） |

以下为冲突点说明（示意，以仓库最终文件为准）。

### 4.1 `xai-grok-shell/Cargo.toml` — features

**本地（HEAD）一侧：**

```toml

```

**官方（upstream）一侧：**

```toml
[features]

dhat-heap = ["dep:dhat"]
# Session synthesis + in-process e2e harness ...
test-support = []

```

**最终（双方保留）：**

```toml
default-bazel = ["test-support"]

```

说明：`[[bin]] chat-history-downgrade` 仍 `required-features = ["playground-tools"]`，故必须保留该 feature。

### 4.2 `run_loop.rs` — `SetSessionModel` 命令臂

**背景：**

- 上游重写了会话主循环（格式与分支远大于本地）。  
- 本地在 `SessionCommand::SetSessionModel` 上增加了 `system_prompt_label: Option<String>`，并在 `handle_set_session_model` 中使用。  
- 若整文件只取 upstream，会 **漏字段导致无法编译**（pattern 与函数签名不一致）。

**冲突形态（概念上）：**

```text
<<<<<<< HEAD
  （旧版 run_loop 压缩格式 + 已含 system_prompt_label 的 match）
=======
  （上游完整新循环 + 无 system_prompt_label 的 match）
>>>>>>> upstream/main
```

**解决步骤：**

1. 整文件采用 **upstream** 的 `run_loop.rs` 主体。  
2. 手工改 match 臂，把本地字段接回去。

**最终关键片段（当前仓库）：**

```rust
SessionCommand::SetSessionModel {
    sampling_config,
    use_concise,
    apply_prompt_override,
    skip_prompt_rewrite,
    auto_compact_threshold_percent,
    system_prompt_label,   // ← 本地补丁
    responds_to,
} => {
    let updated_model_id = session
        .handle_set_session_model(
            sampling_config,
            use_concise,
            apply_prompt_override,
            skip_prompt_rewrite,
            auto_compact_threshold_percent,
            system_prompt_label,  // ← 传入 session 实现
        )
        .await;
    let _ = responds_to.send(updated_model_id);
}
```

配套仍保留（自动合并或未冲突）：

- `commands.rs` 中 `SetSessionModel { ..., system_prompt_label, ... }`  
- `handlers/model_switch.rs` 解析 label 并 `send(SessionCommand::SetSessionModel { ... })`  
- `acp_session_impl/model_switch.rs` 内 `set_system_prompt_label` + 写回 system 消息  
- `xai-grok-agent` 的 `set_system_prompt_label`

---

### 4.3 `read_file/mod.rs` — 工具输入与 skill 全量读

**官方新增（应保留的能力）：**

1. `schema_default_offset()` — schema 上默认 offset=1  
2. `is_skill_markdown()` — `SKILL.md` 或路径含 `skills` 段的 md **全量读取不截断**  
3. 英文 description 与实现细节更新  

**本地一侧：** 同区域多为中文注释/描述字符串差异，**无独立业务逻辑**。

**冲突示例（示意）：**

```text
<<<<<<< HEAD
  // （空行或中文 schemars description）
=======
fn schema_default_offset() -> Option<i64> {
    Some(1)
}
>>>>>>> upstream/main
```

```text
<<<<<<< HEAD
  description = "开始读取的行号……"
=======
  default = "schema_default_offset",
  description = "The line number to start reading from. ..."
>>>>>>> upstream/main
```

```text
<<<<<<< HEAD
  /// 提取文件行内容的结果结构体……
=======
fn is_skill_markdown(path: &Path) -> bool { ... }
/// Result of extracting file content lines ...
>>>>>>> upstream/main
```

**最终：** `git checkout --theirs` 该文件（**完整采用官方实现**）。  
中文注释未强行合并进工具源码（避免与上游大段逻辑手工缠在一起）；行为以 0.2.112 官方为准。

### 4.4 `Cargo.lock`

- 双方均有大量依赖 bump。  
- 解决：采用 upstream lock 为底，再执行：

```bash

cargo check -p grok-session
cargo check -p jike-grok-desktop
```

确保工作区新增 crate 与版本图一致后纳入合并提交。

## 7. 后续建议

1. **推远程前**再跑一轮桌面 `cargo tauri dev` 做会话/切模型冒烟（尤其 `promptId` 与 label）。
