## 2. 官方这批改了什么（1.0.9 / 1.0.10）

摘自 `xai-grok-shell/CHANGELOG.md` 与 `changelogs/1.0.9.md`。

### 引擎 / 可被桌面直接吃到的

| 官方改动 | 桌面要不要动手 |
|----------|----------------|
| 工作流出现在模型 system 提示里（和 skills 并列，可按名启动） | **直接受益**。画布发布的 sidecar 流程更容易被模型点名跑 |
| `/workflow` 支持 `agent_budget` | **可复用、已有投影**：`grok-session` `WorkflowInfoDto.agent_budget` 已有；桌面工作栏可补「子 agent 预算」展示 / 传入 |
| `/workflow` 支持 `effort`（子会话推理强度） | **可复用、桌面未接**。试跑/发布流程时可把当前 Tab 的 reasoning effort 传进去 |
| MCP 多服务器不再拖垮 session 启动 | **直接受益**。桌面 `start_session` 少等 |
| 并发子 agent 限流重试、突发不再 429 | **直接受益**。画布并行节点更稳 |
| 子 agent / 工作流子会话仍拿不到 `workflow` 工具 | 与 1.0.8 一致；桌面不必改 |
| Plan 模式不再把子 agent spawn 误判成改 `plan.md` 外文件 | **直接受益**。计划模式里跑编制/画布子 agent |
| 前台 bash 跑着时发新消息 → 命令改后台，不取消 | **直接受益**（走同一条 `session/prompt`）。桌面 Composer 排队已有，行为更合理 |
| 记忆检索结果改成「历史上下文、需对活源核验」 | **直接受益**。编码壳记忆面板文案可稍后改软一点 |
| 窄 bash always-allow 规则允许写文件 | **直接受益** + 本地仍禁止把 `bash` 本身当 grant |
| MCP 同 URL 不同名不再被合并 | **直接受益** |
| `grok mcp add` 把裸 http(s) 当 HTTP | TUI CLI；桌面设置里加 MCP 仍走 config.toml |

### 几乎纯 TUI / CLI，桌面不必抄

斜杠菜单按最近使用排序、`/plugin` 别名、`/minimal`/`/fullscreen` 热切、status line 进 minimal、dashboard Shift+Tab Auto、`/edit-prompt` 外置编辑器、`/feedback` 附图、`grok clone` worktree 复用、TUI 默认 ask/auto 来回改。

### 结构拆分（合并时碰到）

- 新 workspace 成员：`xai-grok-shell-terminal`（从 `xai-grok-shell/src/terminal` 挪出）
- 工作区 `path_virtualization`、hub 主动鉴权、session `visibility`（隐藏会话）
- `xai-tool-protocol` 增加 `bot_relay`（协议层，桌面暂不用）

## 4. 能不能复用（结论）

**能，而且多数不用改桌面就会变好。** 优先接的桌面活（非本 merge 范围）：

1. **工作流 `agent_budget` / `effort`**：试跑和发布时带上；进度条已有 `agent_budget` 字段。  
2. **模型能按名启动工作流**：确认画布发布名会出现在 listing（引擎已把 workflow 写进 system reminder）。  
3. **记忆面板文案**：标明「检索结果是历史，要对仓库核验」。  
4. 不必做：TUI 斜杠排序、status line、grok clone、bot_relay、session visibility（除非以后要隐藏工具会话走官方 hidden，而不是自建 `thread_tool_sessions`）。

**不要**为这些再写一套引擎。工作流预算、MCP 启动、子 agent 限流都已经在 `xai-grok-shell` 里。
