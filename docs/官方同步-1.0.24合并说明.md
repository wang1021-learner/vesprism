## 2. 官方这批改了什么

摘自 `crates/codegen/xai-grok-shell/CHANGELOG.md` 1.0.17 … 1.0.24。引擎侧多数桌面不用改就会变好。

### Breaking / 行为变化（桌面要盯）

| 官方改动 | 桌面影响 |
|----------|----------|
| **1.0.19** `/loop` 定时任务一律后台跑，不再往对话注入 turn | **要回归** BgTask / 后台任务条；不要再假定 loop 结果以会话消息形式出现 |
| **Folder trust** 闸项目 instructions / skills / project-scope 插件 | **风险**：`grok-session` 目前 initialize 主要是 `terminal(true)` + buffering meta，未见完整 folder-trust 产品流；项目技能可能变少 |
| **1.0.22** 内置 agent 工具优先于同名用户 MCP | **约定**：组装单 / 自定义 MCP **勿与官方工具撞名**；桌面不另做改名层 |
| **1.0.24** TUI：Esc 不再取消 turn（提示 Ctrl+C） | **桌面不必抄**；继续用独立 `cancel_turn` |

### 直接受益（引擎已吃，桌面无额外 IPC）

| 官方改动 | 桌面要不要动手 |
|----------|----------------|
| 子 agent spawn 后立刻发消息；完成后同 agent 续跑；completion 带真实输出 | **直接受益** |
| 子 agent attempt id / lifecycle 整理 | **直接受益**；桌面条/取消 UI 可后补展示 |
| 前台 shell ~15s 转后台文案修正；子 agent/workflow 继承 bash timeout | **直接受益** |
| Workflow pause / stop 控制源增强 | **直接受益**；桌面 `workflowGate` 已放行 pause/resume/stop |
| MCP elicitation 多轮、策略拦截文案更清晰 | **直接受益**（桌面已有 elicit / policy UI） |
| Memory v2 / 启动加速 / 共享 settings fetch / OTel histogram | **直接受益**（引擎侧） |
| 发送消息到已结束子 agent → 续跑而非失败 | **直接受益** |

### 机会（未接，可选）

| 官方改动 | 桌面可做可不做 |
|----------|----------------|
| Desktop app tools 走一等公民 MCP server | 评估是否暴露给组装单 / 电脑操作 |
| Client capability：live user-message echo | `grok-session` 可按需 opt-in（当前未开） |
| `grok-workspaced` daemon（多 folder Computer Hub） | 与桌面 supervised sidecar 并行能力；不必立刻迁 |

### 几乎纯 TUI / CLI，桌面不必抄

Dashboard chrome、J/K 跳转、theme 透明底、欢迎屏行为、pager 表格 URL、voice dictation、Extensions modal 快捷键、Esc/Ctrl+C 提示文案。

## 4. 能不能复用（结论）

**能。** 引擎与子 agent / workflow / MCP 修复桌面直接吃；本轮**不必**平行实现 agent。

推送前硬门槛：

1. 提交回灌后的 `Cargo.lock`
2. `cargo check -p grok-session -p vesprism-desktop`（本机建议 jobs=1 / debug=0，防 OOM）
3. `cd crates/vesprism-desktop && node scripts/verify.mjs`
4. 手动：冷启动 / 发消息 / 权限 / 多 Tab；顺带看 **loop 后台化**、**项目 skills（folder trust）**、子 agent

**不要**为 TUI Esc 行为改桌面取消键；**不要**发明新的 subagent steer ACP。

不必做：gboom、pager 搬家、bot_relay 扩契约、Dashboard TUI chrome。
