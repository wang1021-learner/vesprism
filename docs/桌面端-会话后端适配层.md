# 桌面端 · 会话后端适配层

> **状态：记下，暂不实现。**  
> **日期：** 2026-08-23  
> 目的：以后换引擎时，已接的桌面功能（回顾、问答、记忆、hunk、画布试跑等）不必重写 UI。  
> 不是现在换引擎，也不是把别家主循环拷进仓库。

## 1. 问题

现在一条能力从按钮到引擎是直通官方的：

```
React  →  bridge.ts sessionExt('x.ai/recap')  →  Tauri session_ext  →  GrokSession  →  spawn_agent_local / ACP
```

`GrokSession::start_spawned` 写死 `spawn_agent_local`。扩展方法名（`x.ai/recap`、`x.ai/hunk-tracker/*`、`x.ai/memory/*`）从 TS 一直传到官方。

换引擎时：界面还能用，但每一处 `x.ai/*` 都要改。功能不是废了，是绑死在 grok 私有方法名上。

## 2. 不改什么

- 官方 `xai-grok-*` 循环、工具、Rhai
- React 外观（横幅、画布、编制）
- 不引入 app-server / exec-server / V8，不把 Codex / Hermes / DSH 源码搬进本仓库
- 第一步不做第二套引擎实现

## 3. 为什么缝在 grok-session

四层分工：

| 层 | 该知道 | 不该知道 |
|---|---|---|
| 桌面 React | 有没有回顾、点了要回顾、怎么画摘要 | `x.ai/recap`、`spawn_agent_local` |
| Tauri `commands.rs` | 这个 Tab 请回顾 | grok 还是别的进程 |
| **grok-session** | 怎么起会话、怎么说话、事件怎么译成 `SessionEvent` | 画布 JSON、编制 yaml |
| 官方 grok-build | 模型循环和工具 | Vesprism 产品形状 |

换引擎变的是「怎么起、RPC 叫什么、事件怎么对上现有 `SessionEvent`」。这三件已经都在 grok-session。

不放桌面：UI 抽象了，Rust 里仍 `spawn_agent_local`。  
不放 `commands.rs`：那只是 IPC 信封。  
不放 `xai-grok-shell`：合 upstream 更死。

若 `grok-session` 过厚，可再拆薄接口 crate，**Grok 实现仍放 grok-session**。层不变。

画布 JSON、编制 yaml 仍在桌面。只有「试跑」碰引擎（今天编 Rhai + `/{id}`），换引擎时再决定继续用 grok 跑流程，或另写编译目标。

## 4. 目标形态

```
桌面 → SessionBackend（发消息 / 设模式 / 记忆 / 审阅 / 跑流程…）
         └── 今天唯一实现：GrokSession（spawn_agent_local + ACP）
         └── 以后可选：HermesAcp / DshAcp（不在本次范围）
```

桌面始终 `invoke('start_session')`、听 `session-event`。事件类型继续用现有 `SessionEvent`（Recap、Monitor、工具调用等）。

## 5. 分步（均未开工）

### 第一步：只留缝，行为为零变化

在 `crates/grok-session`：

1. `SessionCaps`：本后端会哪些能力（`recap` / `ask_mode` / `memory` / `hunks` / `rewind` / `git_write` / `imagine` / `schedule` …）。Grok 实现里能做的全 `true`。
2. `StartOpts`：`cwd`、`model`、`effort`、`flows`，以后加 `agent_type`。不要让桌面拼 `x.ai/flows`。
3. `SessionBackend` trait：从现有 `GrokSession` 方法收（`start` / `resume` / `send` / `interject` / `cancel` / `set_model` / `set_mode` / `apply_composition` / `rewind` / `fork` / MCP / skills / workflows / `ext` 逃生口）。
4. `GrokSession` impl 该 trait：内部仍 ACP；`recap()` 仍调 `x.ai/recap`。
5. `state.rs` Actor 握 backend（枚举或 `Box<dyn …>`），今天只造 Grok。

桌面 TS 可暂不改，`session_ext('x.ai/recap')` 仍进 Grok 的 `ext()`。加测试：假 backend 能 start/send，证明 Actor 不直接依赖 `GrokSession` 类型。

**预计改动文件：** `crates/grok-session/src/` 新 `backend.rs`；`lib.rs` impl；`vesprism-desktop/src-tauri/src/state.rs` Start 走 trait。

### 第二步：桌面改具名命令

已接功能不再喊官方方法名：

| 现在（TS） | 改为 |
|---|---|
| `sessionExt(..., 'x.ai/recap')` | `invoke('session_recap', { tabId })` |
| `setSessionMode('ask'\|'plan')` | 保持，走 trait `set_mode` |
| `/memory on\|off` | `session_set_memory(enabled)` |
| hunk 的 `x.ai/hunk-tracker/*` | `hunk_list` / `hunk_accept` / `hunk_reject` |
| 万能 `session_ext` | 留下，仅给未收编的 grok 调试 |

前端 `session_caps(tabId)`：没有的能力藏按钮。Grok 下全开，与现在一致。  
`commands.rs`：具名命令 → `ActorCommand::Recap` → `backend.recap()`。

### 第三步：新功能也走这层（需另点头）

| 功能 | 做法 |
|---|---|
| Git 暂存/提交 | trait `git_stage` / `git_commit`；Grok 可用 `x.ai/git/*`，也可用桌面直接 git |
| 一律放行 | `set_always_approve` → Grok `/always-approve` |
| 生图/视频 | `imagine` → `/imagine`；事件带资源，气泡展示 |
| 官方 `.md` Agent | `StartOpts.agent_type` 写入 `session/new` |
| 长驻会话 | 另实现同一 trait，不是 Codex app-server |

OS 沙盒、云环境、V8/exec-server：Windows 桌面仍不做。

### 换引擎时（现在不做）

新 impl：`start` 改为 spawn 对方 ACP 进程，事件填进同一套 `SessionEvent`。Caps 没有的返回不支持。不改 MessageList、画布、编制。

## 6. 和「被官方绑死」

刻意绑定的是 **agent 合同**（ACP + 官方工具循环），不是 React。  
缝留在 grok-session 之后：桌面绑「我们的会话 API」，Grok 实现绑官方。官方升级只改一个 impl；换引擎加一个 impl。

现在每多接一个 `x.ai/*` 到 TS，以后拆一次疼一分。本文是防锁死，不是换引擎方案。
