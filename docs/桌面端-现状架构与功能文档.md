### 0.3 专用面板 Tab（`utilityKind`）

侧栏入口调用 `openChatTab({ title, utilityKind })`，在会话区 **TabBar 开 Tab**（不是侧栏内嵌页）。  
**同一 `utilityKind` 若已存在则 `switchTab` 复用，不重复堆叠**（技能 / 工具 / MCP / 自动化任务 可长期保持打开）。  
主区 `AppMainBody` 按 `utilityKind` 切换：

| utilityKind | 标题 | 面板 | 官方 API |
|-------------|------|------|----------|
| `mcp` | MCP | `McpPanel` | `x.ai/mcp/list`、`toggle`、`upsert`、`delete` |
| `tools` | 工具 | `ToolsPanel` | `x.ai/commands/list`（session → `tools` + `commands`） |
| `skills` | 技能 | `SkillsPanel` | `x.ai/commands/list`（**cwd** 扫描；命令 meta 含 `scope`+`path`） |
| **`workflows`** | **自动化任务** | **`WorkflowsPanel`** | **`x.ai/workflows/list`**（空则回退 commands 中 `workflowPath` 条目） |
| `null` | 普通对话 | MessageList + Composer | 既有会话流 |

- **MCP**：列表 / 启用禁用 / **可视化添加**（stdio 或 HTTP）/ 删除本地配置；展开看 tools。  
- **工具**：当前 Agent 可用工具（分类、搜索、复制名）；斜杠命令子页；**浏览不执行**。  
- **技能**：按作用域分组（local / repo / user / …）；展示**用途**（`description` / `when_to_use` 等）；复制 `/name`；「使用」= **填入 Composer**（`fillInChat`）并退出专用面板回到普通对话。  
- **自动化任务**：浏览已发现 Rhai 工作流（`.grok/workflows/*.rhai`）；按 source 分组；描述 / 适用场景 / 路径；复制或「使用」填入 `/name`。**不**在面板内执行编排（启动仍走对话斜杠 / 引擎 `workflow` 工具）。

## 1. 技术栈与运行形态

| 层 | 技术 | 版本/备注 |
|----|------|-----------|
| 桌面壳 | Tauri 2 | `tauri 2.11`，插件：`dialog`、`log`（debug）；权限 `core:default` + `core:window:default` + `dialog:default` |
| 前端 | React 19 + TypeScript + Vite 8 | 入口 `src/main.tsx` |
| 状态 | nanostores + `@nanostores/react` | **Tab 分片 map 为事实源** + 活跃 tab 投影到全局 atom |
| 虚拟列表 | `@tanstack/react-virtual` | `MessageList.tsx`；时间线复用 virtualizer |
| Markdown | Streamdown + `@assistant-ui/react-streamdown` + KaTeX / Mermaid 插件 | `AssistantMarkdown.tsx` |
| 样式 | `index.css` → `styles/*.css` 分域 | 浅色中性灰；圆角统一 ~6px；内嵌 JetBrains Mono |
| 后端会话 | `grok-session` | 内存 duplex + ACP；**每 Tab 独立 LocalSet 线程** |
| 引擎 | `xai-grok-shell`（workspace） | 官方 agent 库内嵌，非子进程套壳 |
| 会话索引 | `rusqlite` → `$GROK_HOME/sessions/threads.sqlite` | 侧栏索引 |
| 全文搜索 | 官方 `session_search.sqlite`（FTS5） | `search_sessions`；命令面板 / 侧栏共用 |

## 3. 架构与数据流

### 3.1 总览（多 Tab）

```
┌──────────────────────────────────────────────────────────────────┐
│  React UI                                                        │
│  TabState map（事实源） ──投影──► $messages / $permission / …    │
│  bridge.invoke(tabId, …)  ·  listen('session-event') 含 tab_id  │
└───────────────────────────────┬──────────────────────────────────┘
                                │ Tauri IPC
┌───────────────────────────────▼──────────────────────────────────┐
│  commands.rs                                                     │
│    open_tab / close_tab / restart_tab  → SupervisorCommand       │
│    send_prompt / load_session / …      → 按 tab_id 查 tabs 表    │
└───────────────┬───────────────────────────────┬──────────────────┘
                │                               │
    Supervisor 线程（LocalSet）          tabs: Mutex<HashMap<TabId, cmd_tx>>
                │                               │
                │  每 tab 一个 TabActor           │
                ▼                               │
┌───────────────────────────────┐               │
│  run_tab_actor(tab_id)        │◄──────────────┘
│  唯一 GrokSession / LocalSet  │
│  emit(FrontendEventEnvelope{  │
│    tab_id, event })           │
└───────────────┬───────────────┘
                │ ACP duplex
┌───────────────▼───────────────┐
│  xai-grok-shell agent         │
│  持久化 summary / updates     │
│  session_search.sqlite        │
└───────────────────────────────┘
```

### 3.2 后端：Supervisor + TabActor

| 组件 | 职责 |
|------|------|
| `spawn_supervisor` | 启动 `grok-supervisor` 线程；返回 `supervisor_tx` + 共享 `tabs` 表 |
| `SupervisorCommand` | `OpenTab` / `CloseTab` / `RestartTab` |
| `run_tab_actor` | 原单会话 Actor；`cmd_rx` 全释放时优雅退出 |
| Panic 重建 | 连续 panic ≤ **3** 次自动起空壳并发 `tab_recovering`；超限发 `tab_failed` 并从 tabs 表移除 |
| 手动 `restart_tab` | 关旧、起空壳、`tab_recovering { attempt: 0 }`，计数清零 |

`AppState`：

```text
tabs: Arc<Mutex<HashMap<TabId, UnboundedSender<ActorCommand>>>>
supervisor_tx: UnboundedSender<SupervisorCommand>
workspace_cwd_override: Arc<Mutex<Option<PathBuf>>>
```

所有会话级 command 经 `send_cmd(state, tab_id, …)` 路由；tab 不存在则报错。

### 3.3 前端：Tab 分片 + 投影

对齐官方 pager「`agents: IndexMap` + 共享 models」思路：

| API | 作用 |
|-----|------|
| `TabState` | `sessionId / chatId / messages / status / phase / permission / chatTitle / composerInput / cwd / error` |
| `createTab` / `removeTab` | 注册 / 注销 map + `$tabs` |
| `patchTab` / `patchActiveTab` | **唯一写路径**（写 map；仅活跃 tab 投影到 `$messages` 等） |
| `switchTab` | 设 `$activeTabId` + 全量投影 |
| `$tabs` / `$activeTabId` | TabBar 列表与当前 id |
| `$models` / `$defaultModelId` / `$reasoningEffort` | **跨 tab 共享** |
| `$chats` / `$workspaceOptions` | 全局历史与工作区选项 |

**约束：** 禁止直接 `$messages.set(...)` 绕过 map（操作函数 `addMessage` 等已改走 `patchActiveTab`）。

事件处理（`App.tsx`）：

1. `ev.tab_id` 路由；已关闭 tab 的迟到事件丢弃  
2. **非活跃 tab 也写入 map**（后台生成 / 崩溃恢复依赖）  
3. `pushTranscriptEvent(ev, tabId)` 按 tab 合并消息  
4. `tab_recovering` → `replayTabAfterCrash`：用 map 快照 `load_session` 或 `start_session` + 重放默认模型  

打开历史（`Sidebar`）：

- 在 await 前锁定 `myTab = $activeTabId`，全程 `patchTab(myTab, …)`，避免切换污染  
- `load_session(myTab, id, cwd)`  

### 3.4 配置与密钥隔离

启动时（`lib.rs`）强制：

```
GROK_HOME = %USERPROFILE%\.vesprism   （Windows；旧路径 `.jike-grok-desktop` 启动时迁移）
```

| 文件 | 用途 |
|------|------|
| `$GROK_HOME/.env` | API Key 明文；Windows 上 `icacls` 收紧权限（尽力） |
| `$GROK_HOME/config.toml` | `[models].default`、`[model.<id>]…`、`[desktop].workspace_cwd` |
| `$GROK_HOME/sessions/` | 官方会话目录 + `threads.sqlite` 索引 |
| `$GROK_HOME/.../session_search.sqlite` | 官方 FTS 索引 |

**原则：** 与 CLI / `grok-gui-poc` 配置隔离；禁止依赖仓库内 `.env`。

### 3.5 工作区 cwd 解析优先级

1. 进程内 `AppState.workspace_cwd_override`（设置后立即生效）  
2. `config.toml` → `[desktop].workspace_cwd`  
3. monorepo 仓库根 / 进程 cwd（兜底）

切换 cwd 后由调用方对**当前 tab** 执行 `restart_session(tabId, cwd)`。

### 3.6 会话生命周期

| `SessionPhase` | 含义 |
|----------------|------|
| `idle` | 初始 |
| `booting` | （预留） |
| `ready` | 可输入 |
| `restarting` | 新建 / 切工作区 |
| `loading` | 打开历史：磁盘投影 + attach |
| `failed` | Tab 连续 panic 超限（TabBar 显示重试） |

| `SessionStatus`（引擎） | 含义 |
|-------------------------|------|
| `unknown` / `initializing` / `idle` / `generating` / `ended` | 来自 Actor 的 `status_changed` |

**冷启动：**

1. `workspaceCwd` → `getModelSettings` → `listSessions(cwd, 80)`  
2. `listenSessionEvents`  
3. `openTab` → `createTab` → `switchTab` → `startSession(tabId, cwd)`  

**新建对话（当前 tab 内）：** `restart_session` + 同步默认模型（侧栏 New chat / Ctrl+N / 命令面板）。  
**新建 Tab：** `openTab` + `startSession`（默认继承当前 cwd）。  
**打开历史：** 磁盘投影秒开 → `beginAttachRuntime(tabId)` → `load_session` → `finishAttachRuntime`。  

**约束：** 单窗口内可多 Tab **并行**会话；每个 Tab 内仍是单一 `GrokSession`。

### 3.7 发送消息与乐观 UI

```
用户点发送
  → generateId('p_') 作为 promptId
  → patchActiveTab 立刻追加 user 气泡 + 清空输入
  → 发送贴底 effect：列表不在底部也强制 smooth 滚回（自己的消息必须可见）
  → send_prompt(tabId, text, promptId)
  → 引擎 user_text_chunk 带回 prompt_id → 同 id 核销
  → invoke 失败：撤回气泡 + 还原输入 + idle
```

**回合归属（§3.13）：** 每条 user 气泡带 promptId；turn_ended 按它匹配归属，
旧回合（被中断）的迟到收尾不会误 seal / 误置 idle 新回合。

### 3.8 标题同步

| 来源 | 路径 |
|------|------|
| 官方 `SessionInfoUpdate` | `session_update_to_event` → `TitleChanged` |
| 扩展 `SessionSummaryGenerated` | `GuiClient::ext_notification` → `TitleChanged` |
| 前端 | `title_changed` → `patchTab({ chatTitle })` → TabBar / `$tabs` 标题 |

打开历史时先用侧栏列表标题，再等引擎事件刷新。

### 3.9 Rewind（后端就绪，前端未接）

`grok-session` 暴露：

- `get_rewind_points()` → ACP `x.ai/rewind/points`  
- `execute_rewind(target_prompt_index, mode, force)` → `x.ai/rewind/execute`  
  - `mode`: `all` / `conversation_only` / `files_only`  

桌面 command：`get_rewind_points` / `execute_rewind`（需 `tab_id`）。  
**前端 bridge / UI 均未封装**，功能矩阵标为后端就绪。

> **产品语义：** 这里的「撤销」是 **会话历史回滚**（对话/文件改动回到某 prompt 点），不是 git 回滚源码。

### 3.10 多 Agent（官方能力接入）

**引擎：** 主 Agent 工具 `spawn_subagent`；父会话收 `x.ai/session_notification`：

| 通知 | 前端 type | 作用 |
|------|-----------|------|
| SubagentSpawned | `subagent_spawned` | 登记子任务 |
| SubagentProgress | `subagent_progress` | 进度 |
| SubagentFinished | `subagent_finished` | 结束态 + output |

**扩展 command（经父 Tab Actor）：**

| API | 用途 |
|-----|------|
| `x.ai/subagent/cancel` | 取消运行中子 Agent |
| `x.ai/subagent/get` | 查询快照 |
| `get_session_messages(childId)` | 磁盘投影子全文 |

**会话隔离（本轮）：** 子会话事件带独立 `session_id`——`GuiClient` 记录本会话 id，
`session_notification` 中 `session_id ≠ 本会话` 的更新**直接丢弃**（子 agent 的任务提示/思考/
正文不再混入父会话消息流，子任务状态走上表三条通知独立通道）。

**子 agent 权限：** `request_permission` 同样按 `session_id` 区分——子会话的权限请求
**自动选 AllowOnce**（桌面端无子视图交互，等价官方 YOLO），不再弹父会话审批条。

**产品边界：**

| 能力 | 状态 |
|------|------|
| 父读子进度 / 磁盘全文 / 取消 | ✅ 消息流**内嵌子任务行**（scaffold，点开 attach viewer）+ cancel/get + 磁盘投影 |
| 新标签打开子会话 | ✅ `openSubagentTab`（viewer：load_session + attached_as_viewer） |
| 父 Composer 代发消息到子会话 | ❌ 官方无 API；须在**子 Tab** 说话 |
| Workflow / Goal / Monitor 可视化 | ❌ 未做 |
| `list_running` 启动对账 UI | ❌ 未做（运行中主要靠推送通知） |

> 子任务行**不做实时 diff / 不展开内容**（用户决策）：只显示「修改了文件 + 状态 + `+N −M`」，详情去右栏。

### 3.11 AI 结构化提问（`ask_user_question`）

```
Agent 工具 ask_user_question
  → ACP 反向请求 x.ai/ask_user_question
  → GuiClient::ext_method 发出 SessionEvent::UserQuestionRequest
  → 前端：浮动问卷 + 消息流 ask_user 工具卡 + 时间线入口
  → respond_user_question(JSON outcome) → oneshot → ExtResponse
  → 工具卡回写 answers 预览
```

支持：多题、单选/多选、Other 备注、Esc 取消、plan 模式「先聊再说 / 跳过访谈」。

### 3.12 流式输出链路（引擎合帧 + 单一滚动写手）

```
引擎 agent_message_chunk / agent_thought_chunk
  → ReplayBuffer 合帧（bufferingSettings：maxItems=32 / maxBytes=2048 / maxDurationMs=16）
  → grok-session 事件 → state.rs 透传（信封带 tab_id）
  → 前端 pushTranscriptEvent → applyTranscriptEvent（拼接/去噪/工具 upsert）
  → patchTab → MessageList（TanStack Virtual + use-stick-to-bottom）
```

- **合帧在引擎侧**（官方扩展点，未改 shell 源码）；前端**不做**二次 rAF 合帧（曾做过，已删——双重合帧白延迟一帧）
- **滚动单一写手**：`use-stick-to-bottom`（initial/resize `instant`）负责 scrollTop；
  流式只做「清尾条缓存 + measureElement」，`tailLive` = 全局 generating || 尾条 isStreaming || 尾条工具 in_progress
- **估高（增量预测）**：`HeightRecord {h, len}`——尾条以「上次实测高度」为锚，
  只叠加本帧新增字符行数 × 20px（宁高勿低），消除「每帧向上顶」推挤感；
  流式长文上限 2400px / thought 720px / tool 按 diff+preview 估展开
- **大上下文**：≥200 条 overscan 12→16（流式 10）；高度缓存软上限 800（仅条数变化时扫）；切会话清缓存
- **发送贴底**：新增 user 气泡强制滚回（smooth 弹簧动画），流式跟滚保持 instant
- **渲染**：`AssistantMarkdown`（Streamdown 增量解析 + tailBoundedRemend 尾部修复 +
  GFM Alert + 懒加载 code/mermaid 插件）；流式行 `contain: layout` 锁布局

### 3.13 回合归属（中断后立刻发送的竞态修复）

`turn_ended` 事件带 `prompt_id`，与消息流**最后一条 user 气泡的 promptId** 对比：

| 情况 | 行为 |
|------|------|
| 匹配（正常收尾） | seal 全部流式行 + `status idle` + 清 permission/userQuestion |
| **不匹配（旧回合迟到收尾）** | 只 seal **user 之前**的旧区；新回合正在流式的行保持流式；**不置 idle** |

修复场景：AI 输出中点停止 → 立刻输入发送 → 旧回合 `turn_ended(cancelled)` 迟到
到达，旧逻辑会把新回合流式行定稿（回复切两半）并把状态置 idle（生成中显示"未生成"）。

- 悬浮输入区；Enter 发送、生成中停止  
- 模型热切换 + 推理强度（messages backend 过滤不可用档）  
- 工作区下拉 + 浏览（空对话可切）  
- 长粘贴折叠（阈值 800 字符）

### 5.6 `MessageList` + `ChatTimeline`

- **A 方案（scrollTop 单一写手）：** `use-stick-to-bottom`（initial/resize `instant`）+ TanStack Virtual（见 §3.12）  
- 大上下文：≥200 条 overscan 16、高度缓存上限 800、切会话清缓存  
- 估高：`HeightRecord` 增量预测（实测锚点 + 新增行 × 20px）；thought/tool 按内容估高  
- 发送新消息强制贴底（smooth）；回到底部按钮弹簧动画（`JUMP_SPRING`）  
- 权限审批发起行计算（最后一个 in_progress 工具行）→ 内嵌审批条定位  
- **时间线：** 提取 user 消息预览；≥ **4** 条显示；hover 展开列表；点击 `scrollToIndex`；滚动联动 active tick  

### 5.7 `MessageItem` / Spinner

- 角色：`user` / `assistant` / `thought` / `tool` / `system`  
- Braille spinner（CLI 对齐：帧序列、~7.5fps、字形回退、思考灰 / 工具绿）  
- **assistant 正文：** `AssistantMarkdown`（Streamdown 增量解析；GFM Alert；懒加载 code/mermaid；`<preview>` 清理；流式尾部修复）  
- **工具行（会话内不展示 diff）：** 一行摘要 `[图标] 标题 · 状态 · 耗时 [+N −M]`；展开只看工具输出 preview（长输出截断 + 复制钮）  
- 子任务行：安静 scaffold（spinner / 失败 `!` / 类型图标），`contain: layout`  
- 历史会话工具行**带耗时**（磁盘 timestamp 解析 → `toolCall.timing`）

### 5.8 `RightPanel`

- Tab：`文件` | `源码` | `差异`（`store.RightPanelTab`）  
- **打开文件绑定：** `$rightPanelFile`（文件名）+ `$rightPanelFilePath`（绝对路径）+ `$rightPanelOutput`（全文）→ 切「源码」  
- **源码视图：**  
  - `pre` 不折行；**横向 + 纵向**滚动（长行 / 长文件）  
  - 内边距加大（约 `14–18px`），滚动条 thin + gutter，避免贴边  
  - body 交给内层滚动（`overflow: hidden` + 子面板 `min-height: 0`）  
- **差异：** 读 `$rightPanelFilePath` → `fileWorkingDiff`；顶栏显示文件名 + 状态角标 + **刷新**  
  - 未打开文件：提示先在「文件」中打开源码  
  - `clean`：与 HEAD 一致  
  - `modified` / `untracked`：`DiffLines` 展示 old/new（**Cursor 风格**：红删绿增 + 2px 边条，
    无 `+/-`/`@@` 噪音；固定行高 20px + 200 行分块 + 400 overscan **行窗口虚拟化**；长行可横向滚）  
  - `not_git` / `missing`：说明文案  
- 文件树 SVG 图标；`list_dir` / `read_file_text`（体积上限由后端校验）  
- 可拖拽改宽（`$rightPanelWidth`）  
- **打开右栏时自动折叠侧栏**（`$sidebarAutoCollapsed`）；关闭时若为自动折叠则恢复  
- **无** Artifact HTML 预览

### 5.11 `Permission.tsx`（对齐 Hermes）

- **内嵌审批条**（`InlinePermissionBar`）：渲染在**发起审批的工具行正下方**（positional，事件不带结构化参数无法按命令匹配，agent 同一时间只阻塞一个审批）；工具行不在视口时输入框上方**兜底浮层**（`PendingApprovalFallback`）
- **组合主按钮**「运行 ⌘⏎ ▾」+ 独立「拒绝 Esc」；下拉含引擎给的非 allow/deny 选项：**「本次会话允许」「总是允许」（+ 确认弹窗防误点）**、拒绝（红）
- **权限记忆（`permissionMemory.ts`）**：once（不记）/ session（同命令本会话自动放行，内存按 tab 分，切会话清）/ always（localStorage 持久化，跨会话）
- 记忆命中 → App 自动 `respondPermission`（`pickAllowStrict` 只认明确 allow；找不到不自动放行）
- `parsePermissionDescription` 解析引擎文案（类型/工具/命令/目标）；Ctrl/⌘+Enter 运行、Esc 拒绝（capture）
- 失败处理：respond 失败收起弹窗 + toast「审批未送达」；turn_ended / 记忆自动放行时清残留弹窗
- 子会话权限后端自动 AllowOnce（§3.10），不弹父会话
