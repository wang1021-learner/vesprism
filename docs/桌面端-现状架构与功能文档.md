## 0. 一句话结论

桌面端是 **Tauri 2 壳 + React 19 前端 + 进程内 `grok-session`（ACP 管道包装官方 `xai-grok-shell`）** 的单窗口 Agent 客户端。  
重构后代码量明显收敛（前端约 20 个 TS/TSX + 单文件 `index.css`）。主路径可用；本轮已补齐 **发送乐观 UI、消息虚拟列表、CLI 同款 Braille spinner、权限真实 option 回传** 等项。仍有 Diff 侧栏 / 深色主题 / M1 发布硬门槛等产品债，见 §6–§7。

## 1. 技术栈与运行形态

| 层 | 技术 | 版本/备注 |
|----|------|-----------|
| 桌面壳 | Tauri 2 | `tauri 2.11`，插件：`dialog`、`log`（debug） |
| 前端 | React 19 + TypeScript + Vite 8 | 入口 `src/main.tsx` |
| 状态 | nanostores + `@nanostores/react` | 无 Redux / Zustand |
| 虚拟列表 | `@tanstack/react-virtual` | `MessageList.tsx` 已接入 |
| Markdown | Streamdown + `@assistant-ui/react-streamdown` + KaTeX / Mermaid 插件 | `AssistantMarkdown.tsx` |
| 样式 | 全局 `index.css` | 浅色中性灰主题，**无深色** |
| 后端会话 | `grok-session` | 内存 duplex + ACP；`LocalSet` / `current_thread` |
| 引擎 | `xai-grok-shell`（workspace） | 官方 agent 库内嵌，非子进程套壳 |
| 会话索引 | `rusqlite` → `$GROK_HOME/sessions/threads.sqlite` | Codex 风格侧栏索引 |
| 全文搜索 | 官方 `session_search.sqlite`（FTS5） | `search_sessions` command |

**启动命令：**

```bash
cd crates/jike-grok-desktop
npm run desktop          # cargo tauri dev（先 vite :9527）
npm run desktop:build    # 打包
npm run dev              # 仅前端 HMR（无 Tauri 时 IPC 不可用）
```

**开发 URL：** `http://127.0.0.1:9527`（`tauri.conf.json` / `package.json` 一致）

## 3. 架构与数据流

### 3.1 总览

```
┌─────────────────────────────────────────────────────────────┐
│  React UI (WebView)                                         │
│  store atoms  ←→  bridge.invoke / listen('session-event')   │
└───────────────────────────┬─────────────────────────────────┘
                            │ Tauri IPC
┌───────────────────────────▼─────────────────────────────────┐
│  commands.rs  ──send──►  Session Actor (state.rs)           │
│                          单线程 LocalSet + 唯一 GrokSession  │
└───────────────────────────┬─────────────────────────────────┘
                            │ ACP duplex (内存管道)
┌───────────────────────────▼─────────────────────────────────┐
│  xai-grok-shell agent（spawn_agent_local）                  │
│  持久化：summary / updates.jsonl / session_search.sqlite    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 配置与密钥隔离

启动时（`lib.rs`）强制：

```
GROK_HOME = %USERPROFILE%\.jike-grok-desktop   （Windows）
```

| 文件 | 用途 |
|------|------|
| `$GROK_HOME/.env` | API Key 明文；Windows 上 `icacls` 收紧权限（尽力） |
| `$GROK_HOME/config.toml` | `[models].default`、`[model.<id>]…`、`[desktop].workspace_cwd` |
| `$GROK_HOME/sessions/` | 官方会话目录 + `threads.sqlite` 索引 |
| `$GROK_HOME/.../session_search.sqlite` | 官方 FTS 索引 |

**原则：** 与 CLI / `grok-gui-poc` 配置隔离；禁止依赖仓库内 `.env`（启动时若用户目录无密钥，会尝试从旧版包目录迁移一次）。

### 3.3 工作区 cwd 解析优先级

1. 进程内 `AppState.workspace_cwd_override`（设置后立即生效）  
2. `config.toml` → `[desktop].workspace_cwd`  
3. monorepo 仓库根 / 进程 cwd（兜底）

切换 cwd 后需调用方自行 `restart_session`。

### 3.4 会话生命周期（前端）

| `SessionPhase` | 含义 |
|----------------|------|
| `idle` | 初始 |
| `booting` | （预留） |
| `ready` | 可输入 |
| `restarting` | 新建 / 切工作区 |
| `loading` | 打开历史：磁盘投影 + `load_session` attach |
| `failed` | （预留） |

| `SessionStatus`（引擎） | 含义 |
|-------------------------|------|
| `unknown` / `initializing` / `idle` / `generating` / `ended` | 来自 Actor 的 `status_changed` |

**打开历史主路径（Codex 风格）：**

1. `get_session_messages(id)` 磁盘投影秒开 UI（可走内存缓存）  
2. `beginAttachRuntime()` → `$attachingRuntime=true`，期间丢弃 transcript 类回放事件  
3. `load_session` → 后端 `GrokSession::resume` + drain 回放（`skip_transcript`）  
4. `finishAttachRuntime()` / `replay_complete`  
5. 之后实时 `session-event` 经 `pushTranscriptEvent` → `applyTranscriptEvent` 写 `$messages`

**新建对话：** `restart_session(cwd)`（空会话自动清理）+ 同步默认模型。

**约束：** 全局**单一** `GrokSession`（无多标签并行会话）。

### 3.5 发送消息与乐观 UI

```
用户点发送
  → generateId('p_') 作为 promptId
  → 立刻 $messages 追加 user 气泡（乐观）
  → 清空输入框
  → send_prompt(text, promptId)  // meta.promptId 进引擎
  → 引擎 user_text_chunk 带回 prompt_id
       → mergeUserTextChunk：同 id 核销，不插第二条
  → invoke 失败：removeUserMessageByPromptId + 还原输入 + idle
```

关键文件：`App.tsx`（`onSend`）、`lib/sessionTranscript.ts`（`mergeUserTextChunk` / `removeUserMessageByPromptId`）、`bridge.sendPrompt(text, promptId?)`。

### 3.6 Actor 事件转发注意点

- `forward_event(..., current_session_id)` 需 5 个参数；主循环与 `drain_session_events_until_quiet` 均应传入当前 `session_id`。  
- `TurnEnded` 时可异步 `upsert_thread` 刷新侧栏索引（依赖 `current_session_id`）。

## 5. 前端模块说明

### 5.1 `App.tsx`

- 启动：`workspaceCwd` → `getModelSettings` → `listSessions` → `listenSessionEvents` → `startSession`  
- 布局：侧栏 | 主视口（Header / Error / Messages / Composer / Settings）| RightPanel  
- ErrorBoundary 三层：侧栏 / 主界面 / 消息区  
- 快捷键：**仅** `Ctrl/Cmd+N` 新建（自定义事件 `jike:new-chat`）  
- **发送：** 乐观用户气泡 + `promptId`；失败回滚  
- **权限事件：** 写入 `options: { id, name, kind }[]`  
- **未实现：** `Ctrl/Cmd+K` / `,` 打开设置（旧 M3 文档写过，现码无）

### 5.2 `Sidebar.tsx`

- 品牌 + New chat  
- 会话按 **工作空间 → 时间** 两层分组；当前工作区默认展开  
- 官方 FTS 搜索弹层（debounce 250ms，支持 snippet / bootstrapping 提示）  
- 会话菜单：重命名、删除（确认）  
- 打开历史：缓存 + 磁盘投影 + `load_session`  
- 底部打开设置

### 5.3 `Composer.tsx`

- 悬浮输入区；Enter 发送、生成中显示停止  
- 模型下拉热切换；支持 reasoning 的模型可切换思考强度  
- 工作区下拉 + 浏览目录（空对话可切换，有用户消息后禁用）  
- 上下文 token 用量条；可选拉 `get_session_usage` 详情  
- 长粘贴折叠为 paste block（阈值 800 字符）

### 5.4 `MessageList.tsx`（虚拟列表）

- `@tanstack/react-virtual`：只挂载可见区 + `overscan: 12`  
- **动态测高：** `measureElement` + `heightCacheRef`（按 `messageId` 缓存，含行间距 24px）  
- **估高：** 按 role / 文本长度，缓存命中优先  
- **贴底策略：** 只信 `el.scrollTop = el.scrollHeight`（**不用** `scrollToIndex` 贴底；估高未收敛时 scrollHeight 才是真底）  
- 上滑锁定 +「回到底部」平滑 `scrollTo({ top: scrollHeight - clientHeight })`  
- 打开历史：先 `opacity:0` 再贴底防「先顶后底」  
- 流式：高度差补偿 + 强制重测最后一项

### 5.5 `MessageItem.tsx`（活动行 + Spinner）

- 角色：`user` / `assistant` / `thought` / `tool` / `system`  
- **思考：** 默认折叠；流式文案「思考中… Xs」；结束后「思考了 Xs」  
- **工具：** 一行摘要 + 可展开 preview；diffs 为简易 `+/-` 前缀，**非** LCS 侧栏  
- **进行中指示：** `BrailleSpinner`（对齐官方 TUI）  
  - 帧：`⠋⠙⠹⠸⠼⠴⠦⠧`（与 `braille_spinner_frames` 同码点）  
  - 帧率：~7.5fps（133ms/帧，对应 CLI `SPINNER_DIVISOR=4` @ ~30fps）  
  - Windows WebView：启动时 canvas 测字形；无 Braille 则回退 `| / - \`  
  - 字体优先 `Segoe UI Symbol`（避免 Consolas 空白）  
  - 布局：spinner 在文案**左侧**（CLI 布局）  
  - **颜色（对齐 CLI turn_status）：**  
    | 场景 | Spinner 色 | CSS |
    |------|------------|-----|
    | 思考 live | 灰 `--text-secondary` | `.thought-line.is-live` |
    | 工具 live | 绿 `--success` | `.tool-line.is-live` |
- 用户长消息：>600 字折叠  
- Assistant：Streamdown（数学插件）；流式时仍走同一组件（无「流式纯文本、结束后再 MD」分流）

### 5.6 `RightPanel`

- Tab：`文件` | `源码`  
- 文件树：`list_dir`（跳过 `.` / `node_modules` / `target`）  
- 点文件：`read_file_text`（512KB 上限）填入源码区  
- 可拖拽改宽（260px～55vw）  
- **无** Diff 标签 / HTML·SVG Artifact 预览 / 从工具卡「预览 Diff」入口（M3 侧栏能力仍回退）

### 5.7 `Settings.tsx`

- 左导航：**通用** / **模型**  
- 通用：工作区路径、浏览  
- 模型：列表增删、默认模型、连接字段、采样（null=不写盘）、推理、密钥状态/写入、高级  
- 保存：`save_model_settings` 全量同步 `[model.*]` + `reload_models` + 可选 `set_current_model`  
- 体量仍大（~48KB），helpers 仅部分拆出

### 5.8 `Permission.tsx`（已修）

- 透传引擎 `options[]`，按钮 `onClick → respond(opt.id)`  
- 按 `kind`（allow / deny / other）选按钮样式  
- Esc → deny 类选项；默认 focus deny  
- 文案中文：「工具权限请求」  
- 响应后派发 `jike:focus-composer` 还焦输入框
