## 2. 还假在哪

按「用户点了应用会不会当真」排序。

### 2.1 持久化是面板草稿，不是会话策略

`apply_composition` 在有 `session_id` 时写入 `thread_compositions`。`get_composition` 能读回来。

开 Tab、`start_session`、`load_session`、崩溃重放 `replayTabAfterCrash` **都不会**再跑 `ApplyComposition`。

质疑：重启后禁用工具和 deny 规则还在吗？不在。注释写「重启后仍可读」读的是表单，不是引擎状态。这叫草稿箱，不叫会话覆盖。

### 2.2 八段面板，三路生效

人设、技能、yolo/auto、工作流、MCP、插件都可以改，点应用 toast「组装单已应用」。其中五路是空操作。

质疑：这是在训练用户不信任这个面板。假开关比没面板更糟。

### 2.3 `disabled` 仍用别名

官方过滤：`disabled.contains(&td.function.name)`。  
真名：`run_terminal_command`、`web_search`、`search_replace`。  
面板占位符仍写 `search, web_fetch`。设计稿示例仍写 `disable: [search]`。P3 单测只测 JSON round-trip。

质疑：`["bash"]` 会不会从模型工具表里拿掉终端？不会。P3 补丁形状对、生效名不对。

### 2.4 yolo / auto 是摆设

`PolicyEngine.mode` 存在结构体上，`evaluate()` 不读。  
规则为空时 apply 把引擎设成 `None`，mode 直接丢弃。  
官方 `_meta.yoloMode/autoMode` 从未被 apply 写入。

质疑：用户在面板选 yolo，下一次权限请求会怎样？和没选一样，仍走审批条（除非另有前端 `permissionMemory`）。两个「自动放行」叠在一起，谁赢？没写。

### 2.5 只读自动放行盖住 deny

`read:**/.env`、禁止 grep 密钥，到不了桌面引擎。  
子会话（workflow 子 agent）同样在规则前被放行。

质疑：以后画布节点引用这份组装单，「只读审查」节点的子 agent 受不受约束？按现在的顺序，不受。这是产品语义，不是边角。

### 2.6 人设段落：文案承诺写文件，代码两头不沾

设计稿和面板 label 仍写「注入工作区 AGENTS.md」。  
apply 不写 `AGENTS.md`（这反而是对的），也**不**注入会话提示。

质疑：用户填了「回复使用中文」，模型会看到吗？看不到。还用 `splitList` 按 `,，` 切段——「回复使用中文，先给方案再动手。」会变成两段垃圾。

### 2.7 「另存为」没有读回

`save_composition` 写入 `~/.vesprism/compositions/<name>.yml`。  
没有 `list_compositions`，面板不能选已存 preset。  
`get_composition` 不走 `resolve_composition`（用户级 + extends + 工作区 + 会话）。有覆盖就整份返回，没有就只看工作区 `agent.yml`。

质疑：配置面写了四级合并，产品入口用了吗？没用。另存为的文件谁消费？没有消费者。

### 2.8 设计稿与代码仍是两套契约

| 设计稿 §2 | 代码 `Composition` |
|---|---|
| `permissions.default` + `auto` | `permissions.mode` |
| `fs:edit **/.env` | `edit:**/.env` |
| `tools.overrides.bash.timeout_ms` | 官方不认这个键 |
| 引擎零改动 | 已经改了官方 `ToolOverrides.disabled` |

照设计稿存 YAML，`deny_unknown_fields` 会拒收。

### 2.9 第二套权限语言还在

官方已有项目级 `PermissionRule`。桌面再养 kind+glob，动作词还多了 allow_once/allow_always。  
接线词汇修了一半（ACP kind），没有经过 `lib.rs` 的单测。  
官方安全预检 vs 桌面 allow_always：未定义。

### 2.10 形状还是闭包 DTO

`workflows.auto_run` 仍在 schema 和面板里，apply 忽略它。  
没有「出过回合禁止切换」。没有把组装 id 写入官方会话日志。五个 Tab 不能引用同一份 `coding` 再改一处全变。

`grok-dsh-poc` 仍是空壳。

## 4. 继续质疑（请先回答再加功能）

### 4.1 产品契约

1. **点「应用」的承诺是什么？** 是「草稿已保存」还是「这个 Tab 从现在起按这张单跑」？现在 UI 说后者，实现接近前者。  
2. **八段里哪些允许出现在 P0 面板？** 建议只留 apply 已接线的三项。其余要么藏，要么标「未下发」。能不能接受先砍面板？  
3. **「另存为」的对象是谁？** 若没有选单、没有 `resolve_composition`，这个按钮是否应该先拿掉？  
4. **会话覆盖是整份快照还是相对用户级 preset 的 diff？** 现在存的是面板整份草稿。五个 Tab 改同一份 `coding` 时，改的是五份拷贝还是一个 id？  
5. **出过回合能不能换组装？** 现在能。换了之后历史里的工具调用按新工具表重放会怎样？有没有锁？

### 4.2 生效与恢复

6. **何时回放 apply？** 仅手动？开 Tab？attach？崩溃重放？fork？现在四处都不回放。哪一处是 P0 必须？  
7. **`disabled` 只挂在下一轮 `send_prompt` 的 `_meta`。** 会话创建时的 `_meta.toolOverrides` seed 要不要写？apply 当下那一轮（若正在生成）算不算漏？

### 4.3 名字与词汇

10. **`disabled` 只认官方函数名，还是做别名表？** `bash`/`search`/`web_fetch` 各自映射到谁？加载时未知名是拒收还是静默无效？

## 5. 优化空间（更新后仍建议这条路）

```
3  官方 waterfall（工具前/后、提示组装）     ← 真要拦再做
2  官方会话原语：disabled（已开口）/ extraSystemSections / permission overlay
1  官方已有：skills · MCP · hooks · pluginDirs · Rhai · yolo/auto
0  桌面：选用 preset + 合并 + apply 到 1/2
```

第 0 层只做选和 apply。面板只暴露已接线通道。

组装单应收成可引用 preset（示意）：

```yaml
id: coding
extends: default
model: { name: deepseek-chat, reasoning_effort: medium }
disable_tools: [run_terminal_command]    # 官方函数名或经别名解析
extra_sections:
  - "回复使用中文，先方案再动手。"
permission_rules:                        # 尽量贴近官方 PermissionRule
  - { action: deny, tool: edit, pattern: "**/.env" }
```

产品规则现在就可以写死，不必先做 UI：

1. 稳定 id，会话和以后的 `agent()` 都能引用  
2. 出过回合不能换  
3. id 写入会话元数据，恢复重建当时那份（**要回放 apply，不是只读草稿**）  
4. 创作是复制再改文件；P0 面板不是八段编辑器

## 8. 第三轮：P1 终端视图

官方架构：终端跑在客户端。引擎 `terminal/create` → 桌面子进程 → `wait` / `output` / `kill` / `release`。落在 `grok-session`、官方零改动，方向对。

已接：`terminal.rs` 注册表 + 截断单测；`GuiClient` 五个 ACP 方法；`TerminalOpened/Update/Exited` → `TerminalList` 卡片。

### 8.1 必须修

**`RefCell` 跨 `.await`。** `spawn_terminal` 在 `registry.borrow_mut()` 期间 `child.wait().await`。同时 `wait_for_terminal_exit` 每 100ms `borrow()`，`output` / `kill` 也会借。官方 pull 模型正好是这条并发路径 → **already borrowed panic**。应先取出 `child`、放下 borrow，再 `wait()`，回来再写 `exit`。

### 8.2 产品诚实

- 无 PTY、无 stdin：是命令输出卡，不是终端仿真。交互命令会挂。  
- Windows `cmd /C` 再拼 `args`：管道 / 引号 / 引擎已带 `cmd` 要手测。  
- UI 拼接 chunk，后端才截断：长任务卡片内存不设上限。  
- `release` 无事件：卡片不消失。  
- `create_terminal` 不按 `session_id` 过滤：子会话终端进父会话顶栏。

### 8.3 和组装层的关系

终端是会话区可视化，不是「这个 Agent 是谁」。不要写进 `Composition`，不要进八段导航。
